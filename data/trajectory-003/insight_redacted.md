# I001

Evidence: L007, L017, L018, L019, L020, L021

Reusing task logic does not preserve an evaluation protocol when the execution layer changes model-role routing. Auxiliary roles are part of the experimental condition, so assignments should be explicit and validated before producing comparative rankings.

# I002

Evidence: L022, L026, L027, L028

The cheapest valid correction depends on interaction structure. Saved single-turn target responses can be rejudged under a replacement judge, while an interactive trajectory must be regenerated when the counterpart changes because later actions depend on earlier messages.

# I003

Evidence: L009, L010, L011

A one-example preflight can establish access, schema compatibility, and basic routing, but it does not establish capacity for a full evaluation. Capacity checks should estimate the full request budget and compare it with applicable account limits before submission.

# I004

Evidence: L010, L011, L012

Separating credentials prevents unintended fallback between execution lanes, but access policy and quota capacity remain independent constraints that require their own validation.

# I005

Evidence: L023, L024, L025

A fixed auxiliary assistant improves comparison among tested user simulators but does not reproduce references collected under several different assistants. Fixed-assistant and provenance-matched studies therefore answer different questions about simulated behavior.

# I006

Evidence: L016, L030, L031

An overall episode mean can obscure suite behavior when one suite contributes more examples and the suites measure different constructs. Suite-level and task-level aggregates are necessary for interpreting comparative results.

# I007

Evidence: L014, L015, L016

A normalization layer makes a multi-suite analyzer easier to extend: shared episode representations allow common tokenization, reference pairing, aggregation, and extension metrics across single-turn and multi-turn outputs.

# I008

Evidence: L029

Routing checks establish which model identifier a client requested, but auditability also requires persisting the provider-returned identifier so later reviewers can detect aliases, fallbacks, or backend substitutions.

# I009

Evidence: L030

Scores inferred by a judge from responses should be described as judge-assessed alignment, especially when the target and judge receive asymmetric context and no independently labeled attributes are available.

# I010

Evidence: L032

Dataset size should be interpreted using the actual sampling unit and evaluated role. Conversation rows, unique tasks, and subsets designed for a different role are not interchangeable measures of coverage, and unavailable selection provenance should remain an explicit limitation.
