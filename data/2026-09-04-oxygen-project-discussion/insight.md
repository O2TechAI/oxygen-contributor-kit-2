# I001
Evidence: L004, L006, L009, L036, L040, L047

From Zihan's perspective, Oxygen's scalable unit is not an automatically generated generic lesson but a fast generate-review-export loop in which a contributor's repeated approvals teach the system what that contributor wants an Agent to learn. Personal preference is therefore part of the target signal rather than annotation noise, and the first practical evaluation is prediction of that contributor's later approved Insights from their earlier ones.

# I002
Evidence: L011, L014, L015, L027, L033, L046

From Zidi's perspective, Oxygen's defensible value comes from longitudinal, same-person human-Agent interaction data, not merely from another summarization dataset. Preserving enough environmental and technical context, avoiding destructive over-redaction, and learning cross-task operating preferences are prerequisites; exact task replay is both hard to verify and too narrow to measure the kinds of help a contributor may actually value.

# I003
Evidence: L021, L023, L029, L035, L039

From Manling's perspective, an Insight is useful only if its learning value can be measured: ideally it should increase the Agent's next-round improvement under a fixed budget, not just resemble one human-written answer. Such an evaluation must first declare whether it targets task-specific expert knowledge or task-independent user preference, and it must accommodate multiple valid Insights rather than treating a single annotation as the sole ground truth.

# I004
Evidence: L020, L041, L044, L045

From Yuxiang's perspective, the most scalable benchmark may be constructed after collecting real trajectories, then used to compare learning from extracted Insights against learning from the original trajectories. This avoids manufacturing tasks in advance, but it is viable only if benchmark construction is grounded in high-quality preference understanding and explicitly controls for topic drift between earlier and held-out trajectories.
